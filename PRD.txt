# Product Requirements Document (PRD)

# Website 360 Campus Tour — Frontend Only dengan Vite

## 1. Ringkasan Produk

Website 360 Campus Tour adalah aplikasi web interaktif yang memungkinkan pengguna menjelajahi area kampus secara virtual melalui foto panorama 360 derajat. Pada tahap awal, produk hanya dikembangkan sebagai frontend tanpa backend dan tanpa admin panel. Semua data lokasi, hotspot, informasi ruangan, dan konfigurasi tour disimpan secara statis dalam file JSON.

Website ini ditujukan untuk calon mahasiswa, orang tua, mitra kampus, mahasiswa baru, dan publik umum yang ingin melihat fasilitas kampus secara online tanpa harus datang langsung ke lokasi.

## 2. Tujuan Produk

Tujuan utama produk ini adalah menyediakan pengalaman virtual tour kampus yang mudah diakses, ringan, responsif, dan informatif.

Tujuan spesifik:

1. Menampilkan foto panorama 360 derajat dari berbagai titik lokasi kampus.
2. Memungkinkan pengguna berpindah dari satu lokasi ke lokasi lain menggunakan hotspot.
3. Menampilkan informasi singkat setiap lokasi, seperti nama tempat, deskripsi, dan fasilitas.
4. Menyediakan navigasi daftar lokasi agar pengguna bisa langsung memilih area tertentu.
5. Mendukung tampilan desktop dan mobile.
6. Menggunakan teknologi frontend modern berbasis Vite, bukan Next.js.
7. Menyediakan struktur data yang mudah dikembangkan menjadi admin panel di tahap berikutnya.

## 5. Platform dan Teknologi

### 5.1 Frontend Framework

Framework utama:

```txt
Vite + React
```

Alasan menggunakan Vite:

* Lebih ringan untuk frontend-only.
* Development server cepat.
* Build sederhana.
* Cocok untuk SPA.
* Tidak membutuhkan server-side rendering.
* Struktur project lebih sederhana dibanding Next.js.
* Cocok untuk deployment di Netlify, Vercel, GitHub Pages, atau hosting kampus.

### 5.2 Library Utama

Rekomendasi stack:

```txt
Vite
React
TypeScript
Tailwind CSS
Photo Sphere Viewer
React Router DOM
Lucide React
```

### 5.3 360 Viewer

Library utama untuk panorama:

```txt
Photo Sphere Viewer
```

Plugin yang direkomendasikan:

```txt
VirtualTourPlugin
MarkersPlugin
GalleryPlugin opsional
MapPlugin atau PlanPlugin opsional
```

### 5.4 Styling

Styling menggunakan:

```txt
Tailwind CSS
```

Alasan:

* Cepat untuk membuat UI responsif.
* Mudah menjaga konsistensi desain.
* Cocok untuk dashboard-like layout, sidebar, drawer, dan overlay.

### 5.5 Routing

Routing menggunakan:

```txt
React Router DOM
```

Contoh rute:

```txt

```

* Pengguna dapat membuka halaman utama.
* Tombol “Mulai Tour” mengarah ke `/tour`.
* Halaman responsif di mobile dan desktop.
* Loading halaman cepat.

## 7.2 Halaman Virtual Tour

### Deskripsi

Halaman utama tempat pengguna melihat panorama 360 dan berpindah antar lokasi.

### Elemen UI

* Area panorama 360 full-screen atau hampir full-screen.
* Sidebar daftar lokasi untuk desktop.
* Drawer daftar lokasi untuk mobile.
* Panel informasi lokasi.
* Hotspot navigasi.
* Hotspot informasi.
* Tombol fullscreen.
* Tombol show/hide UI.
* Tombol kembali ke landing page.

### Acceptance Criteria

* Panorama berhasil ditampilkan.
* Pengguna bisa drag/geser untuk melihat sekeliling.

### Deskripsi

Daftar semua titik virtual tour yang tersedia.

### Elemen Data

* Nama lokasi.

## 7.4 Hotspot Navigasi

### Deskripsi

Hotspot navigasi digunakan untuk berpindah dari satu panorama ke panorama lain.

### Perilaku

Saat pengguna klik hotspot, sistem akan:

1. Menampilkan loading state.
2. Mengganti panorama ke lokasi tujuan.
3. Mengubah informasi lokasi.
4. Mengubah URL jika routing lokasi diaktifkan.

### Acceptance Criteria

* Hotspot terlihat jelas di panorama.
* Hotspot memiliki label saat hover atau tap.
* Klik hotspot memindahkan pengguna ke lokasi tujuan.
* Jika target lokasi tidak valid, sistem menampilkan error non-blocking.

### Deskripsi

Hotspot informasi digunakan untuk menampilkan detail tertentu di dalam panorama, misalnya nama fasilitas, keterangan ruangan, atau catatan khusus.

## 12. Kebutuhan Non-Fungsional

### 12.1 Performance

* Halaman landing page harus ringan.
* Panorama tidak boleh dimuat semuanya sekaligus.
* Gambar panorama dimuat sesuai lokasi aktif.
* Thumbnail boleh dimuat lebih awal.
* Gunakan format gambar yang dioptimalkan.

Target:

```txt
Initial load landing page < 3 detik pada koneksi normal
Perpindahan panorama idealnya < 2 detik setelah gambar tersedia/cache
```

### 12.2 Compatibility

Harus mendukung browser modern:

* Chrome.
* Edge.
* Firefox.
* Safari.
* Mobile Chrome.
* Mobile Safari.

### 12.3 Accessibility

* Tombol memiliki label yang jelas.
* Kontras teks cukup.
* Navigasi utama dapat digunakan dengan keyboard sejauh memungkinkan.
* Gambar memiliki fallback text.
* Tidak hanya mengandalkan warna untuk menunjukkan status aktif.

### 12.4 Maintainability

* Data tour dipisah dari komponen UI.
* TypeScript digunakan untuk mengurangi error struktur data.
* Komponen dibuat modular.
* Tidak hardcode lokasi langsung di komponen viewer.

### 12.5 Scalability Frontend

Walaupun belum ada backend, struktur harus siap jika nanti data dipindahkan ke API.

Contoh prinsip:

```txt
Saat ini: import tourNodes from src/data/tourNodes.ts
Nanti: fetch /api/tour-nodes
```

## 13. Batasan Teknis

1. Tidak ada backend pada tahap awal.
2. Tidak ada admin panel.
3. Semua perubahan lokasi dan hotspot dilakukan oleh developer melalui file JSON/TypeScript.
4. Foto panorama harus sudah tersedia sebelum dimasukkan ke aplikasi.
5. Ukuran file panorama perlu dioptimalkan agar website tidak berat.
6. Browser lama yang tidak mendukung WebGL mungkin tidak dapat menjalankan tour dengan baik.

## 19. Routing Behavior

### 19.1 Saat Membuka `/tour`

Sistem menampilkan lokasi default, misalnya:

```txt
gerbang-kampus
```

### 19.2 Saat Membuka `/tour/:locationId`

Sistem mencari lokasi berdasarkan `locationId`.

Jika ditemukan:

* Set sebagai lokasi aktif.
* Tampilkan panorama lokasi tersebut.

Jika tidak ditemukan:

* Redirect ke `/tour`.
* Atau tampilkan pesan “Lokasi tidak ditemukan”.

## 20. Error Handling

### 20.1 Panorama Gagal Dimuat

Tampilkan pesan:

```txt
Panorama gagal dimuat. Silakan coba lagi atau pilih lokasi lain.
```

Aksi yang tersedia:

* Coba lagi.
* Pilih lokasi lain.
* Kembali ke halaman utama.

### 20.2 Hotspot Target Tidak Ada

Jika hotspot mengarah ke lokasi yang tidak tersedia, sistem tidak boleh crash.

Tampilkan toast atau pesan kecil:

```txt
Lokasi tujuan belum tersedia.
```

### 20.3 Browser Tidak Mendukung WebGL

Tampilkan fallback:

```txt
Browser Anda belum mendukung tampilan 360. Silakan gunakan browser terbaru.
```

## 22. Risiko dan Mitigasi

### Risiko 1 — Foto panorama terlalu besar

Dampak:

* Website lambat.
* Pengguna mobile kesulitan membuka tour.

Mitigasi:

* Kompres gambar.
* Gunakan WebP jika memungkinkan.
* Lazy load panorama.
* Gunakan thumbnail kecil.

### Risiko 2 — Hotspot sulit ditentukan

Dampak:

* Navigasi antar lokasi tidak akurat.

Mitigasi:

* Buat mode debug sederhana untuk melihat yaw/pitch.
* Catat koordinat hotspot saat testing.
* Dokumentasikan posisi hotspot di file data.

### Risiko 3 — Mobile interaction kurang nyaman

Dampak:

* Pengguna sulit klik hotspot atau kontrol.

Mitigasi:

* Gunakan ukuran tombol minimal 44px.
* Hindari overlay terlalu banyak.
* Gunakan drawer/bottom sheet.

### Risiko 4 — Struktur data tidak siap untuk backend

Dampak:

* Sulit dikembangkan menjadi admin panel.

Mitigasi:

* Gunakan type data yang rapi.
* Hindari hardcode data di komponen.
* Pisahkan data, UI, dan logic navigasi.
